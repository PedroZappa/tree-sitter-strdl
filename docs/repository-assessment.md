### Generated artifact changes

`tree-sitter generate` with CLI 0.27.2 changed these committed files:

- `src/parser.c` — the generated header changed from `Automatically @generated by tree-sitter v0.25.8` to `Automatically @generated by tree-sitter`.
- `src/tree_sitter/array.h` — updated to the newer generated helper implementation.

No source grammar change was made. The changes are attributable to regenerating with a newer CLI than the one recorded in `package.json`.

### Resolution

The repository adopted the newer generator path:

- `tree-sitter-cli` is pinned to `0.27.2`.
- Generated artifacts use ABI 15.
- The minimum supported runtime floor is Tree-sitter 0.25.
- Node.js, Python, Rust, Go, and Swift dependency declarations were updated where applicable. Python uses `~=0.25.0` because plain `~=0.25` would permit 0.27 releases.
- Generated artifacts were regenerated with the pinned CLI. A second generation produced byte-identical `src/parser.c`, `src/grammar.json`, `src/node-types.json`, and `src/tree_sitter/array.h`.
- Node.js, Python, and Go binding tests passed; the Swift library build passed; Rust and Swift tests remain unverified for environmental reasons.

See [compatibility.md](compatibility.md) for the version matrix and validation details. Query compilation succeeds, but capture behavior still needs explicit tests.

## Syntax coverage inventory

Captured on 2026-11-25 from `grammar.js`, `test/corpus/`, `src/node-types.json`, and temporary parse probes. Probes were parsed with `tree-sitter parse --json-summary` and `--cst` using CLI 0.27.2. They were not committed as fixtures.

Statuses:

- **Supported**: a dedicated grammar rule produces the expected structure.
- **Partial**: some forms parse, but the required construct is narrowed or lacks dedicated structure.
- **Missing**: no dedicated grammar support; probes failed or produced unrelated nodes.
- **Opaque**: content is accepted as string payload with no internal syntax structure.

| Required construct | Status | Grammar evidence | Corpus evidence | Notes |
| --- | --- | --- | --- | --- |
| Variable declarations (`var`, `let`, `const`) | Supported | `variable_declaration`, `lexical_declaration`, `variable_declarator` | `variable_var.txt`; `let` in `arrow_funcs.txt`; `const` probe only | All three keywords parse; `const` has no committed corpus case. |
| Assignments and expressions | Partial | `assignment`, `_initializer`, `expression` | `$:` assignments in `array_literal.txt` and `objects_args.txt` | `$:` and custom `label:` pattern assignments parse. JavaScript-style `x = 1` fails; assignment is only available in declarator initializers. |
| Function calls and nested calls | Supported | `function_call`, `commaSepTrailing` | `function_call.txt`, `number_args.txt`, `array_literal.txt`, `objects_args.txt` | Direct calls and nested calls parse as nested `function_call` nodes. |
| Member expressions and method chaining | Partial | `method_call`, `chained_method` | `function_call_chained.txt`, `objects_args.txt`, `arrow_funcs.txt` | Only `.name(...)` method calls are supported. Plain `.foo` fails; `x["foo"]` parses as an identifier followed by an array, not member access. |
| Arrow functions and callbacks | Partial | `arrow_function` | `arrow_funcs.txt` | Only one identifier parameter and an expression body are supported. |
| Function parameters | Partial | `arrow_function.parameter` | `arrow_funcs.txt` | Zero, multiple, and rest parameters fail; no function-declaration parameter list exists. |
| Arrays | Supported | `array` | `array_literal.txt` | Array elements are expressions. |
| Objects | Supported | `object`, `pair` | `objects_args.txt` | Object literals parse with identifier, string, or number keys. |
| Object properties and shorthand properties | Partial | `pair` | `objects_args.txt` | `key: value` pairs parse; shorthand `{ foo }` fails. |
| Destructuring | Missing | None | None | Object and array destructuring probes failed. |
| Spread and rest syntax | Missing | None | None | `s(...xs)` and `(...xs) => 1` failed. |
| Arithmetic expressions | Partial | `binary_expression`, `additive_expression`, `multiplicative_expression` | `number_args.txt` covers division; additive probe only | `+`, `-`, `*`, and `/` parse. `%` and `**` failed. |
| Logical and comparison expressions | Missing | None | None | `a && b` and `a === b` failed. |
| Unary expressions | Missing | None | None | `-a` and `!a` failed. |
| Conditional expressions | Missing | None | None | `a ? b : c` failed. |
| Optional chaining | Missing | None | None | `a?.b` failed. |
| Nullish coalescing | Missing | None | None | `a ?? b` failed. |
| Template literals and interpolation | Partial | Backtick branch of `string` | None | Backtick strings parse as opaque `string` nodes; `${name}` is not parsed as an expression. |
| Single-quoted and double-quoted strings | Supported | `string` | Double quotes in `function_call_chained.txt` and `objects_args.txt`; single-quote probe only | Both quote styles parse. |
| Comments | Partial | `comment` in `extras` | None | `//` comments parse; `/* ... */` failed. |
| Parenthesized expressions | Supported | Anonymous `seq('(', $.expression, ')')` in `_base_expression` | None | Probe parsed; parentheses produce no dedicated named node. |
| Relevant import and export syntax | Missing | None | None | Probe parsed `import x from "y"` as separate identifiers and a string, and `export` as an identifier; no import/export nodes exist. |
| Mini-notation | Opaque | `string` | `arrow_funcs.txt`, `objects_args.txt` | Mini-notation is ordinary string content with no grammar-specific nodes or semantics. |

This table compares the implemented grammar against the required list in [AGENTS.md](../AGENTS.md). It is not yet evidence that every supported construct is relevant to real Strudel compositions; that evidence-gathering belongs in Phase 3. No grammar changes were made during this inventory, and the temporary probes should become committed corpus tests when their constructs are prioritized.

## Repository inventory

This repository is a distributable Tree-sitter grammar package for Strudel. Its current architecture is a hand-maintained grammar, generated parser artifacts, six template-maintained language bindings, two official query files, seven corpus tests, and a tag-triggered multi-ecosystem publish workflow.

Captured on 2026-11-25 by inspecting tracked files and current package metadata. Generated/template-maintained status is based on [.gitattributes](../.gitattributes) and [tree-sitter.json](../tree-sitter.json); no binding source file contains an explicit generated marker.

### Architecture and authoritative files

| Area | Role | Status |
| --- | --- | --- |
| `grammar.js` | Authoritative grammar definition | Hand-maintained source of truth. |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/*` | Generated parser and public node types | Generated by Tree-sitter CLI; do not hand-edit. |
| `queries/*.scm` | Official query source | Hand-maintained query files. |
| `test/corpus/*` | Corpus tests | Hand-maintained explicit expected trees. |
| `bindings/*`, `CMakeLists.txt`, `Makefile`, `binding.gyp`, package manifests | Binding implementations and build metadata | Marked `linguist-generated` in `.gitattributes`; currently includes manual ABI 15 changes. Regeneration could overwrite those edits. |
| `docs/*`, `.github/workflows/publish.yml`, `scripts/local_install.sh` | Project documentation, release automation, editor helper | Hand-maintained. |

`tree-sitter.json` enables C, Go, Node.js, Python, Rust, and Swift bindings and disables Zig. Zig template markers remain in `.gitattributes` even though no Zig binding files exist.

### Queries

- `queries/highlights.scm` captures keywords, punctuation, operators, literals, calls, methods, parameters, properties, expressions, and constructors.
- It also hard-codes many Strudel API names into `@function.control`, `@function.audio`, `@function.pattern`, `@function.effect`, `@function.envelope`, `@function.time`, `@function.utility`, `@function.midi`, and `@function.sample` captures. This needs a scope decision before Phase 5.
- `queries/locals.scm` captures scopes, variable/parameter/property/function definitions, and identifier references. Its blanket reference rule and function-call/object-key definition rules need semantic review.
- Only `highlights.scm` is registered in `tree-sitter.json` and `package.json`. `locals.scm` is packaged but not registered.
- No `injections.scm` or `tags.scm` exists. `tree-sitter.json` declares `"injection-regex": "^strudel$"` without a corresponding injection query.
- Both query files compile and execute, but no automated compilation or capture tests exist. Python and Rust query exports are commented out despite queries being copied into packages.

### CI and packaging

- The only workflow is `.github/workflows/publish.yml`. It triggers on any tag push and publishes GitHub, npm, crates.io, and PyPI artifacts through reusable `tree-sitter/workflows` jobs at `@main`.
- There is no pull-request or branch-push validation workflow. Generated-file consistency, query tests, binding tests, formatting, compatibility checks, incremental correctness, and performance checks are not explicitly defined in this repository. The behavior of the upstream reusable workflows is outside this repository and was not audited.
- npm `files` includes grammar, generated sources, Node binding, queries, metadata, `prebuilds/**`, and `*.wasm`. It excludes corpus tests, documentation, scripts, and non-Node bindings. `LICENSE` is not explicitly listed; npm's default inclusion was not verified.
- Version `1.1.8` is aligned across npm, lockfile, tree-sitter metadata, Python, Cargo, CMake, Make, and the existing git tag. The tracked `tree-sitter-strudel.pc` is stale at `1.1.1` with an empty description.
- No changelog or release notes file exists. Publishing occurs automatically on tag push; no explicit approval environment is visible in the workflow.

### Licensing decision

Project declarations in `package.json`, `package-lock.json`, `tree-sitter.json`, `pyproject.toml`, `Cargo.toml`, and `grammar.js` now use the SPDX identifier `AGPL-3.0-only`. No copyright or SPDX license headers were found in binding sources or generated parser files. Existing published `1.1.8` artifacts still declare MIT and will require a future release to align their metadata.

#### History and published-artifact evidence

Captured on 2026-11-25 from git history and public registry metadata:

- The initial commit `6c8183f` contained a public-domain dedication in `LICENSE`. The later grammar setup commit `0746f51` introduced MIT declarations in `package.json`, `Cargo.toml`, `pyproject.toml`, and `grammar.js`; `LICENSE` remained public-domain.
- Commit `9986341` deliberately replaced the public-domain `LICENSE` with the full AGPL-3.0 text. Its commit message contains no rationale, and no package metadata was changed in that commit.
- Version `1.1.8` was tagged in `5e199a8` on 2025-08-01, after the AGPL change. npm `1.1.8` metadata points to that commit and declares MIT; its published tarball includes an AGPL-3.0 `LICENSE` file and an MIT `package.json`.
- crates.io `1.1.8` declares MIT and its published crate includes an AGPL-3.0 `LICENSE` file. PyPI `1.1.8` declares `License: MIT` and `License-File: LICENSE`; its published source distribution includes an AGPL-3.0 `LICENSE` file.
- Earlier releases published before the `LICENSE` change, such as npm/crates.io/PyPI `1.1.7`, declare MIT consistently.

This evidence established the conflict before the owner decision. The decision resolves the repository's license direction; it does not change the metadata of already published artifacts.
